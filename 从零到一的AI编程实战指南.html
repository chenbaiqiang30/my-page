实战干货详解
🎯

MVP思维：小之又小的艺术

核心
MVP最小可用方案，不需要一次到位，只要把关键节点打通就行...
1
MVP的核心：只解决暂时用其他工具解决不了的那个关键节点。就像做工作流，核心可能只有一个节点，把那个节点搞定就行。
2
爬虫案例：MVP就是从目标网站爬一条数据保存到本地，不管是文本、Excel还是JSON。能做到这一步就算成功，剩下的都是扩展。
3
扩展维度：① 更多数据 ② 指定数据筛选 ③ 更多输出格式（Excel、飞书） ④ 更多网站（性能扩展）
💡 实战技巧

如果爬取有障碍（如小红书反爬），可以先手动下载数据，验证后续处理流程。等流程跑通后，再考虑自动化爬取的需求。

⚠️ 避坑提醒

小红书、微信小程序这类平台反爬机制很强，不建议新手一上来就挑战。建议从公开的新闻网站开始练习。

🐛

错误调试：与AI有效沟通

方法
描述问题时不要自己加工，要复制原始错误信息，描述客观现象...
1
黄金法则：一次只改一个Bug！连着描述多个问题，AI可能会理解歧义，以为它们之间有关联。
2
正确描述模板：「当我点击【XX按钮】后，页面【具体响应】，但我预期应该是【期望结果】」
3
差异对比法：描述「预期情况」和「实际情况」的差异，AI能更快定位问题
// ❌ 错误示范 "页面报错了，不知道为什么" // ✅ 正确示范 "当我点击上传文件按钮并成功上传文件后， 页面弹出错误提示：'当前处于离线模式，AI分析不可用' 请修复此问题"
💡 进阶技巧

可以让AI主动添加日志：「为了修复当前问题，请适当添加日志，我会在运行后把F12的输出告诉你」

⚠️ 多次修改失败怎么办

如果多次尝试都改不出来，说明代码可能已经逻辑混乱了。这时候建议：让AI重写该功能模块，或根据需求文档重新生成。

🛠️

工具选择：适合的才是最好的

建议
纯小白建议直接用Enter或秒搭，不需要写一行代码，打开网站就能用...
1
纯小白首选：Enter 或 秒搭。不需要写代码，打开网站就能用，能实现大部分需求。
2
进阶工具：Claude Code、Cursor、Trae等IDE。需要一定的环境配置能力，但功能更强大。
3
产品形式建议：优先做Web应用，不要一上来就做小程序。Web应用不依赖任何平台，打开浏览器就能访问。
💡 工具选择原则

工具不重要，idea才最宝贵。不要在工具选择上耗费太多精力，能实现需求就是好工具。

🔗

API接入：Token与授权的那些坑

方法
注意区分临时Token和长期Token，调试页面生成的是临时授权码...
1
授权码类型：SAT开头 = 服务访问令牌（长期有效）；调试页面生成的是临时授权码（会过期）
2
国内模型不需要中转：智谱、Minimax等国内模型可以直接调用，不需要Cloudflare中转
3
调试策略：先用明文API Key跑通流程，确认没问题后再迁移到环境变量或数据库
// Supabase Edge Function 常见问题 // 需要关闭 JWT 验证才能正常调用 // 位置：Supabase → Functions → 选择函数 → Details → 关闭 Verify JWT
⚠️ 常见踩坑

每次从调试页面复制的Token都是临时的，看起来能用但第二天就失效。要去「服务访问令牌」处生成长期令牌。

💾

数据库与后端：知识库 vs 数据库

建议
知识库只能做切片召回，不能拿出完整的用户档案；需要完整数据就用数据库...
1
知识库：适合做语义检索，通过关键词召回相关片段。但只能返回切片，不能返回完整档案。
2
数据库：适合存储结构化数据，可以查询完整的用户信息。适合做用户画像、个人档案。
3
混合策略：个人档案存数据库（用于上下文），详细记录存知识库（用于细节召回）
💡 数据分层策略

用户原始数据 → 提取特征 → 生成个人档案（压缩版）。后续对话基于档案，需要细节时再召回原始数据。

长期运行代理：让AI"记住"上一班发生了什么

解决代理跨会话持续工作的核心难题

🎯 核心问题：代理的"失忆症"

核心痛点
▼
💡 干货洞见

想象一个软件项目由轮班工程师组成，每个新工程师到岗时都完全不记得上一班发生了什么——这就是当前 AI 代理面临的困境。

❌

失败模式一：想一枪毙命

代理试图一次性完成整个应用，结果在实现过程中丢失上下文，下一个会话接手时发现功能半成品且没有文档。

👆 大白话：就像一个程序员熬夜写了一半代码，第二天自己都看不懂写了啥

✅

解决方案：渐进式开发

每个代理会话只处理一个功能，完成后提交 Git 并更新进度文件，让下一个"工程师"能快速上手。

👆 大白话：每完成一小步就做好交接文档，谁来接班都能继续干

❌

失败模式二：过早宣布胜利

部分功能完成后，后续代理环顾四周就宣布项目完成，实际上还有大量功能未实现。

👆 大白话：干了30%的活就以为全干完了，太乐观了

✅

解决方案：功能清单文件

初始化时创建 200+ 功能的 JSON 清单，每个功能标记为"通过/失败"，代理只能在测试验证后才能标记完成。

👆 大白话：列个详细待办清单，没打勾的就是没做完，骗不了人

🏗️ 双代理架构：初始化 + 编码

创新架构
▼
1

初始化代理（只运行一次）

创建 init.sh 启动脚本、claude-progress.txt 进度文件、feature_list.json 功能清单，并做初始 Git 提交。

2

编码代理（每次会话）

读取进度文件和 Git 日志 → 选择下一个未完成功能 → 实现并测试 → 更新进度 → 提交代码

3

端到端验证

使用 Puppeteer MCP浏览器自动化工具 像真实用户一样测试功能，确保真正可用。

🎯 关键洞见

  • 让代理快速理解工作状态的秘诀：进度文件 + Git 历史
  • 用 JSON 而非 Markdown 记录功能清单，因为模型更不容易错误修改 JSON
  • 强制要求"测试通过才能标记完成"，避免虚假的胜利宣言

⚙️ 工作原理

💻 程序化工具调用：用代码编排，减少 37% Token

全新能力
▼
💡 颠覆性创新

传统方式：每次工具调用都要完整推理，中间结果全部堆积在上下文。
新方式：Claude 写 Python 代码来调用工具，中间数据在沙箱处理，只返回最终结果。

📊

传统方式：预算合规检查

获取 20 人团队 → 20 次调用获取费用（每人 50-100 行项目）→ 2000+ 条明细进入上下文 → Claude 手动比对计算

结果：50KB+ 数据占用

⚡

程序化方式

Claude 写 Python 脚本 → 并行获取数据 → 在沙箱中过滤计算 → 只返回超支人员名单

结果：1KB 结果数据

# Claude 自动生成的编排代码 team = await get_team_members("engineering") # 并行获取所有费用（而非逐个调用） expenses = await asyncio.gather(*[ get_expenses(m["id"], "Q3") for m in team ]) # 沙箱内过滤，只输出超支人员 exceeded = [m for m, exp in zip(team, expenses) if sum(e["amount"] for e in exp) > budget] print(json.dumps(exceeded)) # 只有这个进入 Claude 上下文

👆 大白话：以前 Claude 得一条条看账单再算数，现在它写个脚本让电脑自己算，只告诉 Claude 谁超支了

MCP 代码执行：用代码而非对话调用工具

让代理像程序员一样思考，而非像客服一样一问一答

💡 核心范式转变

MCP（Model Context Protocol）让 AI 连接外部工具的通用协议，就像 USB 让不同设备能互联 是 AI 代理连接外部系统的开放标准。但随着连接的工具越多，Token 消耗呈指数增长。

🔄

传统方式：对话式调用

  • 1️⃣ Claude：我需要获取文档
  • 2️⃣ 工具返回：[完整文档内容进入上下文]
  • 3️⃣ Claude：现在我要更新 Salesforce
  • 4️⃣ 工具返回：[确认信息进入上下文]
  • ⚠️ 2小时会议记录 = 50,000 Token 被复制两次
💻

代码模式

  • 1️⃣ Claude 写代码：获取→处理→更新
  • 2️⃣ 代码在沙箱执行，数据不经过模型
  • 3️⃣ 只返回："已更新 15 条线索"
  • ✅ Token 节省 98.7%

🚀 代码模式的四大优势

  • 渐进式发现：工具以文件形式存在，Claude 按需读取，不用预加载
  • 上下文高效：10,000 行数据可以在代码中过滤，只传 5 行结果给 Claude
  • 隐私保护：敏感数据可自动标记化，真实内容不经过模型
  • 技能持久化：Claude 写的代码可保存为可复用函数，越用越聪明
🛡️

沙箱安全：给 AI 划定"安全游乐场"

减少 84% 权限提示，同时防止代理被恶意利用

⚠️ 安全痛点

Claude Code 需要读写文件、运行命令——这很强大，但也很危险。传统方案是每个操作都问用户"允许吗？"，结果用户疲于点击"批准"，反而降低了安全性（批准疲劳）。

😓

批准疲劳的危害

用户被问太多次后，开始不仔细看就点批准，万一 Claude 被提示注入黑客在输入中偷偷加恶意指令攻击，用户可能无意中批准了危险操作。

🏖️

沙箱方案

划定安全边界：在边界内 Claude 自由工作无需询问，越界才提醒用户。权限提示减少 84%！

🔐 双重隔离机制

📁 文件系统隔离

Claude 只能读写当前工作目录，无法碰系统文件、SSH 密钥等敏感内容。

👆 大白话：只能在自己的房间玩，不能跑到别人房间翻东西

🌐 网络隔离

所有网络请求通过代理服务器，只允许访问白名单域名，新域名需用户确认。

👆 大白话：只能访问批准过的网站，想去新网站得先举手报告

"有效的沙箱必须同时实现文件系统隔离和网络隔离。缺任何一个，攻击者都能找到绕过方式。"

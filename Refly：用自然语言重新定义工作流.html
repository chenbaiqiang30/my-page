但我不太担心：复杂企业场景下，可视化节点的可控性和调试能力是不可替代的。他们更像是在做「低门槛入口」，而我们是「专业级工具」。

他们的亮点是「工作流即机器人」——直接输出到飞书、企微，这个场景在国内企业市场很有杀伤力。

启发：我们也该加强「一键部署到 IM」的能力，降低交付门槛。

说实话，Coze 现在的界面确实「太软件了」。我们有插件市场、有 Bot Store，但用户还是觉得难。黄巍说的「从低代码到纯对话」，值得我们反思。

威胁点：他们开源，我们不开源。对于有定制需求的企业，这是硬伤。

干货拆解

🎬 黄巍的创业心路：从飞书低代码到 AI 原生工作流

低代码四层架构 → AI 来了做减法... ▼
飞书时期

在飞书低代码部门，研究如何让普通用户通过拖拉拽搭建 App。当时的产品叫「飞书智能伙伴创编平台 Aily」——和 Coze 有点像。

ChatGPT 冲击

2022年底，部门「自我换血」，探索 AI + 低代码。黄巍发现了一个关键洞察：

"

传统低代码分四层：Data → Workflow → UI → Page+权限。
AI 来了之后，可以直接做减法。

  • UI 层：大模型已经能很好地生成 UI，不需要拖拉拽了
  • Data 层：可以放到 workflow 的某个节点中做增删查改
  • 权限层：面向 C 端用户时可以简化
核心结论
"

AI 时代的低代码就等于 Workflow

创业启动

传统 workflow 太复杂（N8N、Dify 都是），于是决定做一款AI 原生的 workflow 平台——让普通用户也能搭工作流。

产品演进

最初做过类似 UMAN 的写作软件 → 受百度自由画布启发转向画布产品 → 用户反馈需要「可重复运行」的工作流 → 最终转型为 AI 原生工作流平台。

🔗 一键变飞书 Bot：完整教程

Webhook + 长连接 + 卡片回调... ▼

📝 Step by Step

Step 1：创建飞书应用

打开飞书开放平台 → 企业自建应用 → 创建机器人

例如：ClawdBot V5
Step 2：配置权限

权限管理 → 批量导入 JSON（群聊、消息等权限）→ 申请开通

Step 3：获取凭证

记下 APP_ID 和 APP_SECRET

Step 4：启动长连接

事件与回调 → 配置长连接 → 克隆 Refly 的飞书 Bot 仓库 → 运行命令：

npm start -- --app_id=xxx --app_secret=xxx --api_key=YOUR_REFLY_API_KEY
Step 5：添加事件

添加「接收消息」事件 → 开启「卡片回调回传交互」

Step 6：关联工作流

在 Refly 中：打开工作流 → 集成 → Webhook → 创建 API Key → 粘贴到启动命令

Step 7：发布上线

创建版本 → 后台审核通过 → 创建群 → 邀请 Bot 进群 → 开始对话！

🎉 最终效果

多个 Bot 邀请到同一个群，分别负责不同工作流：

  • @搜索Bot：搜最新 AI 新闻
  • @生图Bot：画一只黄色猫咪
  • @分析Bot：帮我分析这个数据

→ 相当于养了一群数字员工，七嘴八舌帮你干活 🤖🤖🤖

核心 Takeaways

1️⃣ Workflow > Agent（对于重复性任务）

Agent 是一次性的，Workflow 可以每天 Run、可以迭代优化、可以固化成 Skill

2️⃣ 黑箱 → 白箱 是关键

能看到每一步在干什么、用什么模型、什么 Prompt，才能真正掌控和优化

3️⃣ 在工作入口使用 AI 最直观

Claude Bot 火爆的本质 = 让 AI 进入聊天框。Refly 让你把 Workflow 变成飞书 Bot

4️⃣ Skill 才是 OpenClaw 的灵魂

装完工具不知道干什么？因为没有针对你场景的工作流。先搭 Workflow，再接 Bot

5️⃣ 原子化 + 组合 = 最大灵活性

乔木建议：搭建原子化的工作流（生图、生视频、搜索...），然后组合使用

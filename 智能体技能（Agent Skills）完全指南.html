01 技能是什么？为什么需要它？
▼
技能是指令文件夹，封装重复工作流，让AI"一学就会"你的专属任务...

🎯 一句话定义

技能 = 指令文件夹，通过专业知识扩展智能体的能力，让AI能够执行你定义的特定任务。

📦 干货：技能的三大核心价值

🔄
可重复工作流
在非确定性系统中创造可预测输出
🎓
领域专长
教AI"你的方式"做事，而非通用方式
⚡
新能力注入
让AI会它原本不会的事（如特定格式输出）

💡 场景举例：营销活动分析

假设你每周都需要让AI：

  • 读取CSV数据 → 执行数据质量检查
  • 计算漏斗指标（点击率、转化率）
  • 与历史基准对比
  • 生成预算重新分配建议

没有技能：每次都要复制粘贴一大段提示词

有了技能：上传CSV，说"分析营销活动"，搞定！

02 技能的结构与必备组件
▼
SKILL.md是灵魂，YAML前置元数据是门面，references/scripts/assets是扩展...

📁 必需文件：SKILL.md

# 技能文件夹结构 analyzing-marketing-campaign/ ├── SKILL.md # ← 必需！主指令文件 ├── references/ │ └── budget_rules.md # 额外参考文档 ├── scripts/ │ └── process.py # 可执行脚本 └── assets/ └── template.docx # 输出模板/图像

📋 干货：YAML前置元数据（Frontmatter）

--- name: analyzing-marketing-campaign description: | 分析营销活动数据，执行漏斗分析， 生成效率指标和预算重新分配建议。 当用户上传营销CSV或要求"分析活动"时触发。 ---

⚠️ 名称和描述是触发技能的关键！描述要包含"何时使用"的关键词。

📏 命名规则

  • ✅ 小写字母 + 连字符：analyzing-marketing-campaign
  • ✅ 动词+ing 形式：generating-reports, reviewing-code
  • ❌ 避免保留词：不要用 claude-xxx, anthropic-xxx
03 渐进式披露：上下文窗口的省钱大法
▼
只加载必要数据，把上下文当公共资源珍惜使用...

🎯 核心理念

"上下文窗口是公共产品"——添加的数据越多，Token消耗越大，响应质量可能下降。

阶段1：技能加载

只有 name + description 进入上下文

阶段2：技能触发

用户请求匹配描述 → SKILL.md 主体被加载

阶段3：按需加载

需要时才读取 references/、执行 scripts/

阶段4：脚本执行

脚本在上下文窗口之外运行，结果返回

💰 干货：实际省Token案例

📊
预算规则文档
5000字 → 仅在"问预算"时加载
📄
输出模板
LaTeX/Markdown模板按需读取
🐍
Python脚本
代码在外部执行，只返回结果
04 技能 × MCP × 子智能体：协同作战
▼
技能教AI做什么，MCP提供外部数据，子智能体实现并行...

🔗 三者关系类比

把构建智能体想象成建造一栋房子：

  • 工具 (Tools) = 锤子、锯子、钉子 → 基础能力
  • 技能 (Skills) = "如何建书架"的说明书 → 组合工具的工作流
  • MCP = 建材供应商 → 提供外部数据和资源
  • 子智能体 = 分包的工人 → 并行干活、独立负责

🔬 评估技能的方法

像测试软件一样测试技能！

# 示例：生成练习题技能的测试用例 测试查询： - "生成问题并保存为Markdown" - "从LaTeX讲义生成练习题" - "生成PDF格式的测试卷" 预期行为： ✅ 使用正确的库处理输入 ✅ 按指定顺序生成问题类型 ✅ 使用assets/中的正确模板 ✅ LaTeX能成功编译 评估方法： 1. 自动化测试：通过skill-creator评估最佳实践 2. 人工反馈：收集实际使用中的问题 3. 跨模型测试：在不同AI模型上验证
07 通过Claude API使用技能
▼
代码执行工具 + 文件API = 在API中释放技能全部能力...

🔑 关键概念

与Claude AI/Desktop不同，API需要手动配置代码执行环境：

  • 代码执行工具：提供沙盒容器执行bash/Python
  • 文件API：上传输入文件、下载输出文件
  • 限制：API沙盒无互联网（Claude AI有）

💻 干货：API调用示例

import anthropic # 1. 上传技能目录 skill_id = client.beta.files.create_skill( source="custom", files=files_from_dir("./my-skill") ) # 2. 上传输入文件 file_obj = client.beta.files.upload( file=open("data.csv", "rb"), purpose="user_data" ) # 3. 发送请求（带必要的beta头） response = client.messages.create( model="claude-sonnet-4-20250514", betas=["skills", "code-execution", "files"], tools=[{"type": "code_execution"}], container={ "skills": [{"id": skill_id, "version": "latest"}] }, messages=[...] ) # 4. 下载生成的文件 output = client.beta.files.download(file_id)

09 Agent SDK：构建研究智能体
▼
主智能体协调三个子智能体，从文档/仓库/网络研究并综合输出...

🏗️ 架构设计

一个用于学习开源工具的研究智能体系统：

  • 主智能体：协调者，使用 learning-a-tool 技能定义研究方法论
  • docs_researcher：搜索官方文档（WebSearch + WebFetch）
  • repo_analyzer：克隆并分析GitHub仓库（Bash + Read）
  • web_researcher：寻找教程、视频、社区内容

📚 干货：learning-a-tool 技能结构

# 技能定义研究方法论 工作流： 1. 研究阶段 - 文档研究员：查找官方文档 → 提取API/概念 - 仓库分析员：克隆repo → 分析结构/示例 - Web研究员：搜索教程/视频 → 收集社区资源 2. 组织阶段 - 引用 references/progressive-learning.md - 按级别组织：概览 → 安装 → 核心概念 → 实战 → 进阶 3. 输出阶段 - README.md：学习路径指南 - resources.md：链接和参考 - examples/：按级别的代码示例

🔌 与Notion MCP集成

研究完成后，自动将 resources.md 写入Notion页面：

mcp_servers = { "notion": MCPServerConfig( command="npx", args=["@anthropic/mcp-notion"], env={"NOTION_TOKEN": os.getenv("NOTION_TOKEN")} ) } allowed_tools = [ "mcp_notion_*", # Notion全部工具 "Write", "Bash", "WebSearch", "WebFetch", "Task", # 分派子智能体 "Skill" # 读取技能 ]

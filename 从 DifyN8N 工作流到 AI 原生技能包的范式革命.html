关键洞察：套娃式加载机制

Skills采用"用到什么加载什么"的策略。主文档先加载描述元数据，再根据触发条件加载对应的子模块（scripts/examples）。这就像套娃一样，层层递进，避免上下文过载。

▼
Skills是Anthropic推出的结构化能力包，让AI从"被动回答"升级为"主动执行"...

🎯 官方定义

Skills是包含指令、脚本和相关资源的结构化能力文件夹，旨在教会Claude以可重复、可预测的方式完成特定专门任务。

🎓

Claude Code = 高智商应届毕业生（强学习力+推理力）
Skills = 入职培训手册 + 专业工具箱（标准化流程+工具）

这是从提示词工程到程序化知识的本质跃迁——不再依赖概率预测，而是确定性执行。

🏗️ Skills 的文件结构与加载机制
▼
一个标准的Skill包含元数据、触发机制、指令集和附属资源，采用多层次按需加载...

📁 标准目录结构

my-skill/ ├── SKILL.md # 核心文件：元数据 + 触发条件 + 指令集 ├── scripts/ # 可执行脚本（Python/JS/Bash） │ ├── fetch.py # 数据抓取 │ └── process.js # 数据处理 ├── resources/ # 静态资源 │ ├── template.xlsx # Excel模板 │ └── logo.png # 图片资源 └── examples/ # 示例文件 └── sample.md # 输出示例

📝 SKILL.md 核心组成

  • 元数据（Meta）：名称、描述——决定AI能否找到这个技能
  • 触发机制（Trigger）：关键词匹配、语义识别
  • 指令集（Instructions）：执行准则、工作流程
  • 资源引用（Resources）：脚本路径、模板文件
⚠️
最佳实践：控制在300-500行

Skills文件不建议超过500行。过长会增加Token消耗和上下文负担。复杂功能应拆分为多个子模块，通过引用机制按需加载。

🎯 多层次按需加载

Skills采用"套娃式"加载策略，这是其Token高效的核心原因：

  • 第一层：用户输入 → AI扫描所有Skill的描述字段（轻量）
  • 第二层：匹配成功 → 加载该Skill的主指令（核心300-500行）
  • 第三层：执行过程中 → 按需加载scripts/resources（用到才加载）

举例：用户说"帮我生成GitHub热榜报告"，AI只加载描述匹配的Skill，如果用到API部分再加载对应脚本，不用的模块完全不触碰。

🔌 MCP（Model Context Protocol）

MCP是Anthropic定义的"USB接口"，用于连接外部系统：

  • 主要用途：对接数据库、API、第三方服务
  • 比喻：大厨的食材供应链（获取外部资源）
  • 特点：门槛较高，同类MCP容易"打架"，建议装10个以下

🧩 Skills vs MCP 定位差异

维度 Skills MCP
核心功能 本地化知识+流程执行 外部系统连接
使用门槛 低（Markdown为主） 较高（需编码）
准确性 高（确定性脚本） 中等（依赖接口）
可装数量 较多（数十个） 建议<10个
最佳搭档 MCP + Skills 组合才是王道！

📊 Dify/N8N 工作流对比

海老豹的亲身经历："上半年写Dify，下半年不写了"——为什么？

  • Dify/N8N：拖拽配置、语义分支固定、改动需重新加载
  • Skills：自然语言驱动、AI自主拆解、灵活组合
💡
关键差异：AI引擎的语义拆解能力

Dify的语义分支是静态配置——你定义多少分支，它就识别多少。而Claude的AI引擎对Skills做动态语义拆解，智能程度远超传统工作流。这是Skills"降维打击"的根本原因。

📊 案例一：Excel 智能报表生成

场景：101中学八年级期中考试成绩表 → 自动生成可视化分析报告

✅
为什么用 Skills 而非直接对话？
  • 每次生成的图表样式保持一致（领导要的那种标准化）
  • 计算逻辑用本地pandas执行，不用浪费Token让AI算1+1
  • 模板固定，只填充数据，杜绝AI添油加醋

核心技术点：

  • 数据分析用 Python pandas 脚本，确定性计算
  • 图表模板预定义：柱状图、饼图、透视表格式固定
  • 只有复杂的合并、异常处理才交给大模型

🔥 案例二：GitHub 每日热榜推送

需求描述（一句话给AI）：

请创建一个技能包： 1. 爬取GitHub趋势榜前5个项目 2. 生成中文Markdown摘要（项目名、描述、技术栈、Star数） 3. 用Python脚本发送到企业微信

AI自动生成的Skill结构：

  • SKILL.md：定义"GitHub趋势"等触发词，描述功能
  • scripts/fetch.py：爬虫脚本，抓取trending页面
  • scripts/send.py：企业微信webhook推送

组合技能的威力：

如果想生成更好看的报告，再加一个"科技风格HTML生成"的Skill，两个组合就能输出精美的每日简报。

🎨 案例三：公众号文章一键生成

海老豹的亲身实践——固定化那些"懒得写"的部分：

  • 文章头尾模板：固定的关注引导、作者介绍
  • 封面图生成：调用即梦MCP，固定风格
  • 版本记录：每次更新自动追加更新日志
  • 多平台分发：自动改写标题长度适配不同平台
🎯
实际收益

核心内容我自己写（保留灵魂），模板化部分交给AI（省时间）。一篇技术文章从2小时压缩到1小时，且风格统一。

❓ 高频问答 · 实战避坑
▼
Skills能解决RAG吗？多个同类Skill会打架吗？私有化怎么搞？...

Q1: Skills 能替代 RAG 吗？

答：不能，它们解决不同问题。

  • RAG：从海量文档中检索相关内容（如2万份文件中找答案）
  • Skills：将确定性流程标准化执行（如固定格式报告生成）

如果你的需求是"搜索文档上下文"，仍需RAG+向量数据库。Skills适合"重复性工作流程化"。

Q2: 多个同类 Skill 会打架吗？

答：会，但比MCP轻很多。

  • MCP建议装<10个，同类会严重冲突
  • Skills可以装数十个，但同功能的要明确描述区分

例如：两个"公众号文章"Skill，需要在描述中写清"海老豹技术风格"vs"通用营销风格"，让AI能区分。

Q3: 私有化部署效果差怎么办？

答：模型能力是核心瓶颈，没有捷径。

  • 本地小模型（8B/14B）生成效果约50%，复杂Skill基本跑不动
  • 私有化若非强制要求，建议用国内大厂API（智谱/Minimax）
  • Dify/N8N私有化同样面临模型能力问题，不是换工具能解决的

Q4: 远程桌面自动化能用 Skills 吗？

答：部分场景可以，但有局限。

  • 浏览器操作：可以，Gemini Flash多模态识别很快
  • 桌面应用：需结合Playwright/PyAutoGUI等工具
  • 反爬/登录验证：AI也搞不定，需传统RPA+指纹浏览器

大龙虾（Lobster）等工具在探索桌面自动化，但距离"全自动"还有距离。
